# Staff resource API

Base URL: `http://localhost:3001/api/v1` (or your configured port).
Every endpoint below requires `Authorization: Bearer <accessToken>`, obtained from `POST /auth/login`.
Requests and responses use camelCase field names and string IDs. Send JSON numbers for tax and quantities. Prisma monetary values are returned as decimal strings.

## Endpoints and roles

For each resource path, these five endpoints are available:

| Method | Path              | Action                                     |
| ------ | ----------------- | ------------------------------------------ |
| POST   | `/<resource>`     | Create (201)                               |
| GET    | `/<resource>`     | List (200)                                 |
| GET    | `/<resource>/:id` | Read one (200)                             |
| PATCH  | `/<resource>/:id` | Partial update (200)                       |
| DELETE | `/<resource>/:id` | Delete and return the deleted record (200) |

| Resource       | Read                    | Create/update           | Delete         |
| -------------- | ----------------------- | ----------------------- | -------------- |
| `customers`    | cashier, manager, admin | cashier, manager, admin | manager, admin |
| `orders`       | cashier, manager, admin | cashier, manager, admin | manager, admin |
| `order-items`  | cashier, manager, admin | cashier, manager, admin | manager, admin |
| `reservations` | cashier, manager, admin | cashier, manager, admin | manager, admin |
| `activities`   | cashier, manager, admin | manager, admin          | manager, admin |

## Create examples

`POST /customers`:

```json
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "phone": "+254700000000",
  "dietaryPreferences": ["Vegetarian"],
  "notes": "Window seat preferred"
}
```

Optional: `customerNumber` (generated when omitted), `status` (`active`, `suspended`, `inactive`), `dietaryPreferences`, `notes`.

`POST /orders`:

```json
{
  "customerName": "Jane Doe",
  "orderType": "dine_in",
  "tableNumber": "T1",
  "tax": 1.5
}
```

Optional: `customerId` (an existing customer's ID, or null for a walk-in), `orderNumber` (generated when omitted), `tableNumber`, `tax` (a monetary amount, defaults to 0), `status`, `notes`.
Order types: `dine_in`, `takeaway`, `delivery`. Statuses: `pending`, `preparing`, `ready`, `completed`, `cancelled`.
New orders start with a zero subtotal. Subtotal and total are calculated by the server. Marking an order completed sets `completedAt`; moving to another status clears it. Order reads include `items`.

`POST /order-items` after creating an order:

```json
{
  "orderId": "REPLACE_WITH_ORDER_ID",
  "menuItemId": "REPLACE_WITH_MENU_ITEM_ID",
  "quantity": 2
}
```

The server copies the menu item's name and price into a historical snapshot and calculates `lineTotal = unitPrice * quantity`. Create, update, and delete recalculate the parent order's subtotal and total atomically, with retries for serialization conflicts. `total = subtotal + tax`; tax is an explicit amount, not a percentage.

`PATCH /order-items/:id` accepts only `quantity`, for example `{"quantity": 3}`. The original name and price remain fixed. To replace the menu item or move it to another order, delete the item and create a new one. Prices, totals, IDs, and snapshot fields cannot be supplied by clients.

`POST /reservations`:

```json
{
  "customerName": "Jane Doe",
  "reservationDate": "2026-11-17",
  "reservationTime": "18:30",
  "guestCount": 2,
  "tableNumber": "T1"
}
```

Optional: `customerId`, `status`, `specialRequests`. Dates use `YYYY-MM-DD`; time uses local `HH:mm` in 24-hour format. Guest counts must be positive integers.
Statuses: `confirmed`, `seated`, `completed`, `cancelled`, `no_show`.

`POST /activities` (manager/admin):

```json
{
  "type": "order_created",
  "message": "New order received",
  "entityId": "REPLACE_WITH_RELATED_RECORD_ID"
}
```

`entityId` is optional and is a descriptive link, not a database foreign key. The timestamp is generated by the server. Activity types: `order_created`, `order_status`, `order_cancelled`, `menu_updated`, `customer_registered`, `reservation_created`, `reservation_updated`, `low_stock`, `sync`.
Activities are managed through their endpoints; CRUD on other resources does not automatically create activity records.

## Updates, errors, and relationships

PATCH accepts any subset of create fields, except order item updates as described above. Required database fields cannot be set to null. Nullable customer links, order table numbers, and activity entity links can be cleared with null. Unknown fields are rejected. Server timestamps and calculated financial fields cannot be overwritten.

- 400: invalid body, date, enum, quantity, amount, or unknown field.
- 401: missing, invalid, or expired JWT, or inactive staff account.
- 403: staff role is not allowed to perform the action.
- 404: target record not found; creating an order item also checks its order and menu item exist.
- 409: duplicate unique value, invalid database reference, or concurrent transaction conflict after retries.

Deleting an order cascades to its items. Deleting a customer clears customer links on existing orders/reservations while preserving their customer-name snapshots. Deleting an order item updates its parent totals. These endpoints do not implement inventory deduction, payment processing, or table availability checks.
